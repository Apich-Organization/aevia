# 内核约定与持久化

内核清单描述一次构建的算子、重载、单位、物理常数、插件和能力。宿主用它生成接口、选择可用操作并确定缓存标识。清单哈希由确定性字节计算，计算之前将哈希字段清零。注册的约定发生变化时，哈希随之变化。

## 调用与科学计算证据

可以按算子名称选择，也可以用固定签名的 `OpKey` 选中重载。生成的 Aevia 绑定将值转换为内核 ABI 所需形式，并按表示、形状和量纲约定恢复。无法在类型化接口中表达的操作可经动态调用，向宿主返回带类型的错误。项句柄属于一个会话，跨会话使用需要由宿主 API 显式导入。

量纲规则表达参数和结果的相互关系。严格检查拒绝量纲冲突，建议检查保留答案并附加诊断。回调限于发起调用的宿主，并携带已检查的签名。回调失败跨过边界时应保留原始消息。

## 二进制与文本格式

RSSN 的二进制清单与计算记录使用 bincode-next 原生编码。现有公开记录的二进制布局与此前的 Serde 编码器作对照验证。JSON 提供自描述的文本格式，确定性 CBOR 接口保留 Serde 数据模型与字段名。C 使用整型项句柄，通过专门的所有权接口接收和释放分配的文本或字节缓冲区。

Aevia 已检查模块缓存使用 bincode-next 3.2 原生 trait 与模式指纹。文件头含缓存键和完整性校验。文件在本地表中保存名义 ADT 标识，加载时恢复进程内 ID。导入和源码标识均参与生成缓存键，导入接口变更会使依赖者的缓存失效。损坏或版本不符导致缓存未命中与重新编译。

## 兼容性检查

线格式变更须考虑旧二进制生成的数据，以及旧清单生成的语言绑定。约定测试覆盖确定性哈希与往返编码。生成的适配器同源码声明和回放签名进行比对。性能测试分别测量编码、解码和端到端工作量，使分配和校验的开销可见。

## 算子身份随调用传播

~~~text
实际注册的算子、签名和单位 → 排序后的清单 → BLAKE3 身份
                                      ↓
源码调用 → 受检查的重载 → 值转换 → RSSN 调用
                                      ↓
                                值、见证或诊断
~~~

动态分派可按名称查询。`OpKey` 固定期望签名，避免相同拼写选中已经改变的重载。适配器降低实参，按声明的表示、形状与量纲检查取回的值。回调句柄只有在活动回调表中才有意义。项及原生对象句柄属于注册它的会话。

| 边界 | 所有权 |
|---|---|
| Rust 直接调用 | Rust 值与类型化错误 |
| C 接口 | 不透明句柄、字节缓冲区及配套释放函数 |
| 动态库插件 | 版本化 ABI 与原生二进制消息，机器码在宿主进程运行 |
| 源码插件 | 在调用方权限范围内追踪符号定义和规则 |
| 包归档 | 验证签名声明中的发布者与归档字节 |

清单哈希标识某次规则集与算子表的安装，供绑定和缓存感知更改。动态库的可信性、具体实验的输入分别由其他边界决定。

## 一次缓存命中

驱动对源码、已解析导入、权限、编译器身份与整个依赖闭包的接口摘要计算键。`.aevi` 外层包含格式版本、键、长度与正文校验和。bincode-next 原生编码核对正文结构。名义声明以符号键存储，解码器先在当前进程驻留声明，再解析引用。截断或结构不兼容的记录会触发正常检查。依赖实现改变而公共接口摘要相同时，调用者可保留检查结果。

## 源码入口

RSSN 的 `kernel/{manifest,signature,codec}.rs` 管理身份和编码，`kernel/{call,callback,native_objects}.rs` 与 `ffi/mod.rs` 管理调用及归属。Aevia 的 `aevia-rssn/src/{codegen,kernel,value}.rs` 与 `aevia-types/src/rssn_resolve.rs` 连接记录和源码类型。`aevia-types/src/persist.rs` 定义持久正文，`aevia-core/src/disk_cache.rs` 定义文件外层及键。 [验证对应表](07-quality-and-delivery.md)
