# 语言流水线与工具

命令行与编辑器经过同一个前端，因而对源码含义有相同的判断。

```text
源码与包上下文
  → 解析导入 → 记号及布局 → AST
  → 名字、类型、量纲与形状检查 → CheckedModule
  → Core IR → 求值器 → 值、IO 动作及诊断
```

## 前端与加载

`aevia-resolve` 提供依赖模型。`aevia-core::driver` 遍历导入图并按依赖顺序排列模块。依赖包内的模块在该依赖的上下文中解析导入。加载器跟踪文件标识，并在解析后的图上报告循环。嵌入的标准库源码和生成的 RSSN 命名空间与本地源码经过同一检查边界。

`aevia-syntax` 保留源位置，将单位表达式交给后续阶段。`aevia-dim` 实现精确指数代数与单位环境。`aevia-types` 在检查时联系数值表示、量纲、记录行与张量形状。已检查模块保留选中的类型类实例、量纲见证与内核重载，供后续阶段使用。

## 求值与性能

`aevia-ir` 将已检查表达式转换成显式绑定和闭包环境。求值器用槽位存放局部值，并标识尾调用位置。类型化 AST 求值器可作为行为对照。批量及并行原语可以在各工作项之间复用类型化路径。可观察的输出顺序和归约语义遵循语言约定。

大部分 `Int` 运算可以使用内联有符号整数，超出范围时提升为任意精度。稠密浮点张量将分派移出逐元素运算。精确有理数与符号表达式保留精确形式，直到请求近似。启用 JIT 特性时，符合条件的标量函数经 RSSN 转换为本机代码，在运行时保护条件不满足时回到求值器。

## 编辑器与文档接口

`aevia-analysis` 将编译器数据转化为悬停、补全、重命名等语义查询。`aevia-lsp` 管理 JSON-RPC、打开文件的内存版本以及诊断发布。格式化与文档工具使用语法树。格式化通过比较语法树指纹保护程序含义；文档工具使用 `##` 注释，并提取围栏中的程序交给 CLI 检查。
