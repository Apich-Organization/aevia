# 包注册表与文档

Axum 服务器向客户端提供 API，向浏览器提供 HTML。PostgreSQL 保存目录、身份和追加式透明记录。独立归档存储按版本和校验和保留包内容。Leptos 依据视图模型生成 HTML，语言文档工具将公开注释转换为 Markdown 和经过清理的 HTML。

## 发布事务

~~~text
名称、版本和 SHA-256 → 挑战 → 规范声明 ← 签名密钥
    签名声明与归档
        → 验签并消耗 nonce → 检查所有者、归档和依赖
        → 数据库事务 → 插入目录行与待生成文档状态
        → 归档持久化 → 追加透明日志 → 提交
                                      → 唤醒文档工作线程
~~~

授权检查签名密钥、发布者和包所有者，包括明确授权的组织身份。解析源码前先检查归档结构和大小。只有存储成功，才提交版本、关系和透明日志。提交失败可能留下无引用的摘要，相同字节的重试可复用该归档。已消耗的挑战不能重放。下载使用记录的摘要，提供条件请求和 HEAD。计数在发布事务外单独批量提交。

文档工作线程在数据库事务中领取待处理版本。它核验归档，提取公开声明，在阻塞任务中清洗并渲染 Markdown。生成页面与构建结果一同提交。错误记录到相应版本，其他任务仍可继续。数据库事务中断后释放待处理任务。

## 公共阅读与私有执行

官方 Markdown 与标准库 JSON 目录来自公共 HTML 使用的同一份受验证快照。读者可经 `/llms.txt` 或网页响应链接发现这些入口。站点地图列出已发布章节与译本。包有独立的 JSON 搜索、解析和索引入口。这些接口供读取数据。

~~~text
浏览器 POST /api/v1/playground/run
    → 来源、速率与大小检查 → 认证的私有工作服务
    → rootless Podman、无网络、只读镜像及受限 /work
    → 截断输出、超时或退出 → 浏览器文本
~~~

注册中心没有容器控制 socket。工作服务接收源码，并以本地镜像执行固定入口。用户命名空间、丢弃能力以及 CPU、内存、进程和输出限制独立于语言权限约束子进程。

## 源码入口

从 `aevia-registry-server/src/api/publish.rs` 追踪发布，经 `aevia-registry-core/src/{statement,tarball}.rs` 查看签名格式与归档规则。`aevia-registry-db`、`docs_queue.rs` 与 `storage.rs` 实现目录、队列和存储。`http.rs`、`limits.rs`、`playground.rs` 与 `sandbox.rs` 实现请求边界。`seo.rs` 管理数据发现和规范链接。 [部署生命周期](06-operations.md)
