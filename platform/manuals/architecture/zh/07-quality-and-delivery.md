# 质量、持续集成与发布交付

检查应覆盖错误会被观察到的边界。算法单元测试可以证明边界行为，调用者实际收到该结果则需要 ABI 测试。源码检查可以证明文档覆盖率，渲染检查能证明读者实际看到了文档。

| 边界 | 检查 |
|---|---|
| RSSN 算法 | 精确恒等式、参考值、非有限值、退化输入和量纲约定 |
| RSSN 引擎 | 增量与全量搜索对照、稳定提取、重复及并行请求 |
| 语言 | 解析与诊断、类型与量纲规则、AST/IR 对照、分配及性能样本 |
| ABI | 清单和记录往返、生成绑定、C 头文件和冒烟测试 |
| 文档 | 两种语言、生成的标准库、可执行课程及包文档解析 |
| 平台 | PostgreSQL 迁移与事务、包发布和签名流程、HTML 及镜像构建 |
| 编辑器 | stdio LSP 冒烟测试、扩展语法或构建、共享文法检查 |

## 保持正确性与性能可观察

选择最靠近所改接口的 Rust 测试目标，将昂贵的集成验证集中到组合改动之后。并行工作应使用不同的构建目录或机器。将缓存和工作副本分开。发布二进制使用通用目标设置，性能测量固定输入、构建配置和线程数。未测量耗时的优化用可核实的工作量或分配变化来描述。

## 持续验证与发布

两个 CI 工作流运行格式检查、lint、测试、接口生成检查和文档检查。Aevia 还构建平台和编辑器扩展。Linux 与 Windows 运行语言及内核工作区的测试。平台数据库集成使用一次性的 PostgreSQL 服务。汇总门禁要求所有必需任务成功。

推送与 Cargo 版本一致的 `vMAJOR.MINOR.PATCH` 标签后会启动发布流程。`v0.1.0-beta.1` 等预发布版本走同一流程。打标签前可手动运行 **Release** 工作流并启用 **dry_run**。两个仓库都在构建提交上运行完整 CI，生成归档和校验和，并将附件上传到草稿。核对提交和附件后再发布。GitHub 在发布时锁定标签和附件并为它们签发证明。RSSN 的 crates.io 任务还需要在 `crates-io` 环境中批准。

每日构建在仓库默认分支运行，使用 UTC 日期 `nightly-YYYY-MM-DD` 发布不可变的预发布。每个日期标签只使用一次。每日构建不会发布到 crates.io 或更新注册表容器。Aevia 将 RSSN 检出固定到具体提交。正式版本的 RSSN 标签必须与 Aevia 锁文件中的版本一致。每日构建使用配置的 `RSSN_REF` 或 RSSN 的 `v0.3` 分支，同时校验包版本与锁文件一致。

安装器按 Rust 目标三元组选择归档。Windows 使用 ZIP，Linux 和 macOS 使用 tar.gz。安装器先验证 SHA-256 和不可变发布证明，再交给工具链管理器。每个标签对应独立目录，三个命令共用一个活动版本。`stable` 跟随最新发布的稳定版，`nightly` 跟随当前目标的最新每日构建，显式指定的版本保持固定。
