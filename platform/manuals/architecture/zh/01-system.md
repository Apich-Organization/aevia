# Aevia 与 RSSN 系统架构

Aevia 是检查量纲的科学计算语言。RSSN 为它提供符号和数值引擎，同时也提供独立的 Rust 和 C API。平台分发工具链，索引已签名的包，并提供规范、库参考和手册。

| 边界 | 输入 | 输出 |
|---|---|---|
| Aevia 前端 | UTF-8 源码与解析后的导入 | 已定型模块、量纲证据与诊断 |
| Aevia 运行时 | 已检查模块、参数与执行选项 | 值、IO 效果和诊断 |
| RSSN 内核 | 项或类型化值、算子签名与配置 | 约简项、数值与结构化结果 |
| 注册表 | 已验证的发布包及元数据 | 版本化归档、索引、透明日志与生成文档 |
| 教程执行服务 | 简短的独立程序 | 有上限的输出、错误与退出状态 |

## 仓库与依赖结构

从源码构建时两个项目位于相邻目录。语言 Cargo 工作区包含编译器、工具和适配器。平台使用独立 Cargo 工作区和锁文件，引用语言中的解析、包解析和文档工具。发布包时生成文档用的是语言自身的解析器，因此生产注册表可以生成文档而不链接数值引擎。

RSSN 管理算子标识和科学元数据。Aevia 定义语法、语言类型与运行行为。平台负责包协议和部署协议。新增 RSSN 算子通常只需类型或明确的动态边界，不需要修改语言解析器。

## 运行时与进程边界

```text
源码文件或编辑器缓冲区
    → 解析导入与语法 → 检查后的模块 → Core IR → 解释器
                                               ↕ 受检查的值
                                               RSSN 会话
浏览器或 aevia-pkg
    → HTTPS 公共来源 → Axum 注册中心 → PostgreSQL 目录与持久归档
                            ├→ 包文档队列
                            ├→ 挂载文档快照
                            └→ 私有执行服务 → 一次性 rootless 容器
```

上下两条流程通过路径依赖共用包和文档语法，交接点是签名归档和生成的接口。注册中心从已发布包提取注释来渲染文档。教程执行器在独立入口编译执行本次提交的源码。开发者的解释器保留本地权限和内核对象，教程执行器为每个程序建立独立的受限进程。

CLI 从入口文件和模块解析上下文开始。LSP 叠加编辑器中尚未保存的内容，然后复用检查流程和诊断位置规则。DAP 在程序运行时查询帧和值。静态检查通过的文件仍可能在执行时产生错误，这时由调试器报告。

## 权威数据与产物

| 产物 | 权威来源 | 使用方 |
|---|---|---|
| 语言行为 | 双语规范与可执行用例 | CLI、编辑器和用户 |
| 算子签名及可用性 | RSSN 安装的算子表及生成清单 | Aevia 适配器、C 宿主和文档 |
| 包身份与字节 | 版本记录、签名声明与归档摘要 | 解析器、下载及透明日志 |
| 官方文档 | 挂载源码与生成的标准库目录 | 网页、独立 HTML 和 Markdown 读者 |
| 发布身份 | Git 提交、目标三元组、锁文件与不可变附件 | 安装器与部署操作者 |

模块缓存可重新计算，发布归档可重新校验，包数据库恢复需与归档存储配对。这些产物的生命周期分别由消费方决定。

## 源码入口

文件执行从 `crates/aevia-core/src/driver.rs` 进入，编辑器请求从 `crates/aevia-lsp/src/server.rs` 进入。语言与内核交接处分别是 `crates/aevia-rssn/src/kernel.rs` 和 RSSN 的 `src/api/mod.rs`、`src/kernel/call.rs`。平台路由入口是 `platform/crates/aevia-registry-server/src/lib.rs`，数据库操作、Markdown 渲染与 HTML 视图分属不同的 crate。 [注册中心内部结构](05-registry.md) · [部署与生命周期](06-operations.md)
