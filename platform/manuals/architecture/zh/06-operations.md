# 平台运行维护

生产环境包含公开反向代理、内网注册表应用与 PostgreSQL，以及持久化归档存储。可选教程执行器使用独立的无特权 Podman 账号部署。数据库和私有执行端点只绑定到实际需要的网络接口。

## 构建与配置

Bazel 构建 `//:registry_server`，并用 `//:registry_image` 打包镜像。部署配套发布中已有的
注册中心二进制时，可用 `//:registry_image_from_binary`。容器使用传入的可执行文件，Compose
启动带标签的镜像。应用需要数据库 URL、用于校验会话的密钥、公网基础 URL，以及归档数据和
文档挂载的显式路径。[部署手册](https://github.com/Apich-Organization/aevia/blob/main/platform/docs/DEPLOY.zh.md)

## 发布与检查

部署后，通过 HTTPS 验证公开地址、健康端点以及一次注册表读取。确认中英文文档页面和离线 HTML 下载均可用。若启用了教程执行器，运行短示例并观察成功和失败时的响应。确认注册表的环境和挂载中没有管理员及其他服务使用的签名或容器控制接口。

使用固定版本的镜像，并保留 PostgreSQL 与归档备份。升级遵守迁移兼容约定。用独立的数据库和归档目录验证恢复。选择对应同一次发布状态的数据库与归档快照，并在恢复服务接收流量前，检查索引与归档是否一致。

## 更新内容

挂载目录提供规范 Markdown 源或生成的 JSON 参考文档。轮询器检测变更，成功装入候选快照后再发布。条件允许时一次替换完整目录或文件。中文章节与英文章节使用相同的 URL 名。重新装入失败时，仍提供上一个有效快照，并将原因记入应用日志。

## 服务拓扑

~~~text
公共 TLS 代理 → 注册中心监听 → PostgreSQL 与持久归档
                      ├→ 只读规范、标准库和手册挂载
                      └→ 私有工作服务与令牌 → rootless 容器
~~~

配置的公开源决定 Cookie、安全检查与生成的 URL。只在代理会覆盖转发头时信任转发地址。PostgreSQL 与工作服务只连接所需调用方。HTTPS 会话使用主机专属 Cookie，认证响应关闭缓存和来源传递。语言 Cookie 记录偏好，显式 `lang` 参数提供可分享的固定链接。

## 内容发布和恢复

二进制和文档挂载具有独立生命周期。把完整的官方版本放在只读目录中。目录挂载可观察内部原子重命名，直接挂载单文件可能继续指向旧 inode。先准备所有关联文件，再尽量在挂载树内切换目录指针。

每个来源有独立轮询器，文件扫描在阻塞线程运行。连续两次扫描观察到相同候选才开始读取。扫描和读取有上限。Unix 指纹除字节数和修改时间外还包含设备、inode 和变更时间。解析前后核对指纹。成功后用短写锁交换共享 `Arc`，持有旧快照的请求可以完成。损坏 JSON、已发布规范译本或模块缺失，以及不完整的双语手册，都会保留上一份有效版本。重复错误不会持续刷日志，并会延迟重试。确实需要删除受保护的规范章节或标准库模块时，在新实例启动时生效。

## 部署验收

检查 HTTPS 和真实包查询，读取双语章节并下载独立 HTML。请求 `/llms.txt`、其链接到的 Markdown 和 `/stdlib/catalog.json`。核对规范链接与站点地图的域名。在预演部署中替换内容，验证无效更新后的恢复。启用运行器时检查正常程序、失败程序和超时。命令和恢复步骤见[部署手册](https://github.com/Apich-Organization/aevia/blob/v0.1/platform/docs/DEPLOY.zh.md)，实现入口是 `main.rs`、`config.rs`、`reload.rs` 和 `state.rs`。
