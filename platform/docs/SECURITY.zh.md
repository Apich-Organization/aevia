# 注册中心安全

[English](SECURITY.md)

## 发布与签名

每次发布或撤回都由注册中心签发一条有效期为五分钟的声明。发布声明绑定包名、版本和 SHA-256 摘要。只有已绑定的签名密钥可以授权操作，每个随机码只能使用一次。归档持久化后，PostgreSQL 在同一事务中提交版本、依赖元数据和透明日志。客户端可用签名与摘要核验归档，已撤回版本也可验证。 [HTTP API](API.zh.md)

OpenPGP 支持由注册主密钥认证的签名子密钥。新操作要求证书和签名密钥仍然有效，注册中心检查绑定时存储的证书。密钥泄露时，可以从账户页面撤销绑定。撤销后的公钥可用于验证历史发布，但不能授权新操作。SSH 签名使用 Ed25519 和 `aevia` SSHSIG 命名空间。 [OpenPGP 规范](https://www.rfc-editor.org/rfc/rfc9580.html)

归档受压缩大小、解压大小及条目数量限制。归档路径必须是可移植的相对路径。文档生成仅将包源码作为数据解析，生成流程不执行包中的程序。站点会净化包提供的 Markdown，并由浏览器内容策略限制脚本和样式从同源加载。

## 身份与会话

GitHub 和 ORCID 验证发布者身份。OAuth 状态通过提供商专用 Cookie 与发起登录的浏览器绑定，回调时只能使用一次。浏览器会话有效期为 30 天。新会话在 PostgreSQL 中保存经 HMAC 派生的查询键，随机会话值保存在仅对当前 HTTPS 主机有效的 Cookie 中。会话 Cookie 使用 `HttpOnly`、`SameSite=Lax`，并在 HTTPS 下使用 `Secure`。浏览器写入操作同时检查请求来源。API 发布和撤回使用独立于浏览器会话的密钥签名授权。

GitHub 用户和组织通过提供商数字 ID 绑定。GitHub 登录名变更时，Aevia 命名空间仍归原发布者记录。组织授权要求同一组织数字 ID 的有效成员身份和 App 安装访问权限。开始检查时清除旧授权，验证通过后授予最多一天的访问权限。 [已有 GitHub 身份绑定流程](DEPLOY.zh.md#升级时绑定已有-github-身份)

挑战、发布、登录、设备、依赖解析和运行接口设有单客户端与服务总量限制。请求超出频率限制时返回 HTTP 429 和 `Retry-After`。只有在代理会重写传入地址标头时才启用代理地址配置。 [部署指南](DEPLOY.zh.md)

## 运行教程代码

教程运行功能可以独立启用。专用工作进程接受注册中心的已认证请求，每次在新的无根 Podman 容器中运行一个源文件。容器没有网络连接和共享宿主机目录。工作进程限制输入、输出、运行时间和并发数，容器进一步限制 CPU、内存、进程数和可写存储。解释器以空 Aevia 能力集合启动。注册中心独立于工作进程的 Podman 套接字和文件系统。 [部署运行服务](DEPLOY.zh.md#启用教程运行功能)

## 透明日志与问题报告

追加式日志用前一条记录的哈希连接历史。保留一个已知日志头哈希，可以比较后来读取的记录与先前观察到的发布历史。 [注册中心设计](../manuals/architecture/zh/05-registry.md)
